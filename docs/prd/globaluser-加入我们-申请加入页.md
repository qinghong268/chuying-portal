## 1. 页面概述

### 1.1 基本信息

| 属性 | 说明 |
| --- | --- |
| 页面路由 | `/join` |
| 适用角色 | 访客（主转化）；已登录非雏鹰用户亦可提交；已是雏鹰时引导去活动/个人中心 |
| 页面目的 | 收集加入雏鹰计划的申请信息并提交，生成「待审核」申请单供后台加入审核处理 |
| 页面类型 | 前台公开页（顶栏 + 页脚壳） |
| 适配终端 | PC Web；Chrome 90+ / Edge 90+ |
| 入口 | 顶栏「加入我们」；首页主 CTA「加入雏鹰」 |

### 1.2 核心功能（动词短语）

| 功能点 | 类型 | 优先级 | 描述 |
| --- | --- | --- | --- |
| 浏览加入说明 | 新增 | P0 | 展示计划加入价值与审核说明 |
| 填写加入申请 | 新增 | P0 | 表单失焦校验 + 提交全量校验 |
| 提交加入申请 | 新增 | P0 | 创建 JoinApplication，状态「待审核」 |
| 查看提交结果 | 新增 | P0 | 成功页/结果态说明后续审核 |

### 1.3 功能关系（逻辑层级）

```
加入计划
├── 浏览加入说明 [平级]
├── 填写加入申请 [平级]
├── 提交加入申请 [平级]
└── 查看加入申请状态 [平级]（完整进度可在登录后个人侧；本页提供提交结果态）
```

管理侧「审核加入申请」（A03/A04）与本页提交能力**平级对应**，不同角色。

### 1.4 业务规则摘要

1. 访客填写申请 → 状态「待审核」。  
2. 拥有 `join_review` 权限的管理员在后台通过/驳回。  
3. 通过后账号具备雏鹰身份（或激活已有账号）——激活方式 `[待补充]`。  
4. V1 演示环境可与登录演示账号配合；正式注册/登录方式见 F08 待决。

### 1.5 本页不做

- 不做后台审核 UI。  
- 不做支付/报名费。  
- 不做移动端适配。  
- 不在本页完成活动报名或积分申请。

## 3. 区域说明与交互

### 3.1 页头说明

| 区域 | 规则 |
| --- | --- |
| 标题 | 「加入雏鹰计划」 |
| 副文案 | 说明提交后待审核；不堆统计指标 |
| 已是雏鹰 | 检测登录角色为雏鹰时，展示「你已是雏鹰」+ 「去个人中心」`/me` + 「浏览活动」`/activities`，隐藏提交按钮或禁用表单 |

### 3.2 表单区

| 规则 | 说明 |
| --- | --- |
| 校验时机 | 失焦校验 + 提交全量校验；错误文案贴字段下方 |
| 提交按钮 | 防重复点击；请求中显示 Loading，禁用二次提交 |
| 通道关闭 | 若后台关闭加入通道，整页展示「当前暂不接受新申请」`[待补充]` 开关来源 |

### 3.3 结果态

| 状态 | 表现 |
| --- | --- |
| 提交成功 | 替换为成功说明；状态「待审核」；提供返回首页 / 去活动列表 |
| 已有待审核单 | 不重复创建；提示「你已有待审核申请」并展示提交时间（若可识别身份） |
| 曾被驳回 | 允许重新提交为新单（与总览「驳回后再提预留」对齐）；展示上次驳回原因若可查 `[待补充]` |

### 3.4 空 / 错 / 加载

| 状态 | 表现 |
| --- | --- |
| 首屏加载通道配置 | 短暂骨架或按钮区 Loading |
| 校验失败 | 字段下红字，不 Toast 刷屏 |
| 接口 4xx/5xx | Toast 失败原因；表单数据保留 |
| 网络超时 | Toast「网络异常，请重试」 |

## 4. 关键字段与校验

> 字段清单以业务最终确认为准；下表为 V1 建议字段，未钉死项标 `[待补充]`。

| 字段 | 前端 ID | 必填 | 校验规则 |
| --- | --- | --- | --- |
| 姓名 | `name` | 是 | 2–40 字符；trim |
| 手机号 | `mobile` | 是 | 中国大陆手机号正则；trim |
| 邮箱 | `email` | 是 | 合法邮箱格式 |
| 学校/单位 | `org` | 是 | 2–80 字符 |
| 专业/方向 | `major` | 否 | 最长 80 |
| 申请理由 | `reason` | 是 | 建议 20–500 字；精确上下限 `[待补充]` |
| 同意隐私说明 | `agreePrivacy` | 是 | 必须勾选 |
| 附加材料 | `attachments` | 否 | V1 默认不做上传；若需要标 `[待补充]` |

### 4.1 提交后数据

| 字段 | 说明 |
| --- | --- |
| `status` | `pending`（待审核） |
| `createdAt` | 提交时间 |
| `applicantUserId` | 若已登录则绑定；匿名访客策略 `[待补充]` |

## 5. 主流程 / 分支 / 异常

### 5.1 主流程

1. 访客打开 `/join`。  
2. 阅读说明并填写必填项。  
3. 勾选同意说明 → 点击「提交申请」。  
4. 系统校验通过后创建申请单，状态「待审核」。  
5. 页面展示成功结果态；管理员在 A03/A04 审核。

### 5.2 分支流程

| 分支 | 行为 |
| --- | --- |
| 已登录访客 | 可预填姓名/邮箱（若账号已有资料） |
| 已是雏鹰 | 不展示可提交表单，引导个人中心/活动 |
| 从首页 CTA 进入 | 同主流程，无额外参数 |

### 5.3 异常流程

| 异常 | 反馈 |
| --- | --- |
| 必填缺失/格式错误 | 字段级错误，定位到首个错误字段 |
| 加入通道关闭 | 整页不可提交说明 |
| 重复待审核申请 | 提示已有申请，不创建重复单 |
| 服务异常 | Toast + 保留表单 |

## 6. 接口依赖摘要

| 方法 | 路径意图 | 说明 |
| --- | --- | --- |
| GET | `/api/join/meta` | 通道是否开放、文案配置 `[待补充]` |

## 7. 验收要点（AC）

1. 访客未登录可打开 `/join` 并看到完整表单。  
2. 必填项为空时无法成功提交，错误展示在对应字段下方。  
3. 手机号、邮箱格式错误有明确提示。  
4. 未勾选同意说明时不可提交。  
5. 合法提交后生成待审核申请，页面进入成功结果态（非静默无反馈）。  
6. 提交过程中按钮 Loading 且不可连点产生多单。  
7. 角色已是雏鹰时不出现可再次提交的主路径（或提交被拒并提示）。  
8. 顶栏「加入我们」高亮；PC 1366×768 下表单单列可读，无移动端适配要求。  
9. 接口失败时表单内容不丢失。
