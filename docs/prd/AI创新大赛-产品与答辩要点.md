# 雏英官网 · AI 创新大赛要点（简要）

> 日期：2026-08-05  
> 用途：新人入职 AI 创新赛的产品方向与答辩加分参考（非功能 PRD）  
> 配套：`docs/prd/globaluser.md`（V1.5）、`docs/prd/known-gaps.md`

---

## 1. 一句话定位

**雏英计划智能运营助手**：门户把人才培养流程跑通；AI 切入审核预审、催办与文案等高频费人环节——不是「又一个 Chatbot」。

---

## 2. 产品怎么更好（功能外也要先稳）

### 优先补齐「能当真用」

| 优先级 | 事项 | 说明 |
| --- | --- | --- |
| P0 | 部署可打开即用 | 云主机 + 域名 + HTTPS；生产关演示超管后门 |
| P0 | 开户交接可闭环 | 通过已可开户；补通知（邮件/企微）避免只靠复制密码 |
| P1 | 首页吃透 CMS | 后台已能编，首页仍多占位（见 known-gaps CMS-HOME） |
| P1 | 演示数据 | seed 增加已结束活动、样例报名/申请，方便当场演示 24h 窗 |

### 体验与运营感

- 个人中心明确「下一步」：报名 / 补进度 / 交心得  
- 管理端待办队列与一键审批路径短  
- 看板：待审积压、近 7 日入账等可讲清的运营指标  

### 不建议赛前硬上

微服务 / K8s、多租户 SaaS、移动 App、与主路径无关的多智能体炫技。

---

## 3. AI 能力建议（嵌进现有系统）

| 优先级 | 能力 | 为何适合大赛 |
| --- | --- | --- |
| P0 | 心得/专项 **智能预审**（切题、缺项、风险标签；人终审） | 紧贴积分审批；可量化省时 |
| P0 | 驳回原因 / 通过说明 **辅助生成** | 后台立刻能演示 |
| P1 | CMS / 活动文案 **草稿生成** | 对上内容运营 |
| P1 | 学员侧 **窗口与进度催办** | 前台可感、故事完整 |
| 慎做 | 全站闲聊通用 Bot | 易被判套壳 |

叙事要点：**规则引擎 + 模型**（门槛用规则，语义用模型）；**人机协同**；结果写回申请单，不飘在聊天里。

---

## 4. 功能之外的加分点

1. **真实场景**：SoftTong 雏英培养，角色与权限包清晰  
2. **工程方法**：PRD / AC / known-gaps / 测试构建——AI 辅助研发，人做决策与验收  
3. **可交接资产**：公开仓、README 可部署、PRD 可查阅  
4. **边界坦诚**：不做移动端/SSO/商城写清楚，显成熟  
5. **Demo 剧本**：2～3 分钟跑通「加入→报名→交心得→（AI 预审）→审批→积分」  
6. **价值假设**：审核耗时、返工、出稿时间——写清假设即可，忌空喊赋能  

答辩可用三句：

1. 场景对准人才培养运营，不是通用聊天。  
2. 方法上有规格与缺口管理，保证能演示、能讲边界。  
3. 代码与文档可交接，创新可落地、可复用。  

---

## 5. 若时间只够做一个赛点

只做 **积分申请智能预审**：待审队列展示风险/建议；管理员仍点通过或驳回。  
改动面相对小，和 Type1/Type2 强绑定，Demo 冲击力够。

---

## 6. 建议 Demo 路径（约 3 分钟）

1. 访客提交加入（邮箱 contact）→ 管理员通过并展示开户密码  
2. 雏英报名活动 →（或课程进度）→ 提交心得  
3. 管理员打开审批：可选 AI 预审标签 → 通过 → 积分明细可见  
4. 收束：规则管窗口与门槛，AI 管质量辅助，人做最终决策
