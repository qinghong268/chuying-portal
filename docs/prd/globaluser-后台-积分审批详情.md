## 1. 页面概述

| 属性 | 说明 |
| --- | --- |
| 页面编号 | A10 |
| 页面名称 | 积分审批详情 |
| 页面路由 | `/admin/point-apps/:id` |
| 权限包 | `point_review` |
| 适用角色 | 已授予 `point_review` 的管理员；超级管理员 |
| 页面目的 | 核对申请 payload，调整最终分值，通过写积分流水或驳回并必填原因 |
| 页面类型 | 后台详情 + 审批操作 |
| 前置条件 | 已登录且持有 `point_review`；申请单存在 |

### 1.1 审批硬规则

| 动作 | 规则 |
| --- | --- |
| 通过 | 申请状态 →「已通过」；写入 `PointLedger` 流水；入账分值 = **最终分值**（审批人可改） |
| 驳回 | 必须填写驳回原因；状态 →「已驳回」；**不写**加分流水 |
| 最终分值 | 审批人可改；须为正整数；默认带出申请分值 |
| 已终态 | 已通过/已驳回只读，不展示通过/驳回主按钮（可展示审批轨迹） |

驳回后再提：按总览预留「修改后重新提交为新单」；本页不处理复活原单。

## 3. 区域说明与交互

| 区域 | 规则 |
| --- | --- |
| 类型分流 | 根据 `type` 渲染 §2.1 或 §2.2，**不得混用字段** |
| 门槛核验 | 类型一只读展示系统核验结果；若提交后进度回退等边缘情况标警示，仍允许人工裁决 `[待核实是否阻断通过]`；V1 建议：**不阻断**，由审批人判断 |
| 最终分值 | 仅待审批可编辑；失焦校验正整数 |
| 通过 | 二次确认 → 调通过接口 → 成功 Toast「已通过并入账」→ 页变只读 |
| 驳回 | 弹窗必填原因 → 成功 Toast → 只读；列表可看到原因 |
| 返回 | 回 `/admin/point-apps`，尽量保留原 Tab 查询串 |
| 加载 | 详情骨架屏 |
| 404 | 「申请不存在或已删除」+ 回列表 |
| 403 | 无权限页 |

## 4. 关键字段与校验

| 字段 | 场景 | 规则 |
| --- | --- | --- |
| 最终分值 | 通过前 | 必填；正整数 1–9999；可与申请分值不同 |
| 驳回原因 | 驳回 | 必填；trim 后长度 5–500；空则不可提交 |

类型一/二 payload 字段为只读展示，审批页不编辑心得/事项。

## 5. 主流程 / 分支 / 异常

### 5.1 主流程：通过并入账

1. 审批员从列表进入详情。  
2. 阅读对应类型 payload；必要时修改「最终分值」。  
3. 点「通过」→ 确认弹窗 → 确认。  
4. 系统：校验状态仍为待审批；写 `PointLedger`（userId、delta=最终分值、关联 applicationId、操作者）；申请置「已通过」；记录 `pointsGranted`、`reviewerId`、`reviewedAt`。  
5. Toast 成功；按钮隐藏；展示审批记录。

### 5.2 主流程：驳回

1. 点「驳回」→ 填写原因 →「确认驳回」。  
2. 系统：状态「已驳回」；保存原因；**不写**加分流水。  
3. Toast；页只读。

### 5.3 分支

| 分支 | 行为 |
| --- | --- |
| 最终分值改小/改大 | 入账以最终分值为准；建议在流水备注中记录「申请分值→最终分值」 |
| 查看已通过单 | 展示流水关联信息（流水 id 或入账分值）；无再次通过 |
| 并发双开审批 | 后请求返回冲突（如 409）；Toast「该申请已被处理」并刷新 |

### 5.4 异常

| 场景 | 处理 |
| --- | --- |
| 最终分值非法 | 字段错误，不弹确认 |
| 驳回原因为空 | 弹窗内报错，不提交 |
| 通过接口失败 | Toast 失败；状态保持待审批，可重试 |
| 流水写入失败 | 整单事务回滚，不得出现「已通过但无流水」 |

## 6. 接口依赖摘要

| 意图 | 方法 | 路径（示意） |
| --- | --- | --- |
| 申请详情 | GET | `/api/admin/point-applications/:id` |
| 通过 | POST | `/api/admin/point-applications/:id/approve` body: `{ pointsGranted }` |
| 驳回 | POST | `/api/admin/point-applications/:id/reject` body: `{ reason }` |

详情响应须按类型返回不同 `payload`：

- 类型一：`activityId`, `activityTitle`, `activityMode`, `watchProgress?`, `offlineWindow?`, `essay`, `essayLength`, `requestedPoints` …  
- 类型二：`templateCode`, `templateName`, `subject`, `reason`, `requestedPoints` …

---

## 7. 验收要点（AC）

1. 类型一与类型二详情区字段不同，互不串字段。  
2. 待审批可改最终分值；通过后按最终分值写入积分流水，申请为「已通过」。  
3. 驳回必须填写原因，否则无法提交；驳回不产生加分流水。  
4. 已通过/已驳回详情只读，无重复审批按钮。  
5. 通过/驳回均有确认或弹窗；成功有 Toast；失败可重试且数据一致（通过必有流水）。  
6. 无 `point_review` 不可操作；404/403 表现符合全局规范。
