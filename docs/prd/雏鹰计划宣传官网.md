## 2. 需求背景

### 2.1 背景

软通智慧「雏鹰计划」面向计划**管理者**与计划**参与者（雏鹰）**，需要一个可对外宣传、对内承载报名与活动运营的统一 Web 入口。当前构想明确：系统不只做静态宣传，还要覆盖**加入报名、活动报名、积分管理、后台管理**等运营能力；需求后续可能变更，故首期以可演进的模块边界落地。

对标对象为**同类人才培养 / 校园招聘 / 计划宣传官网**（如企业校园招聘站、人才培养计划专题站）：首页叙事清晰、路径短、移动端可读，同时把「报名」与「活动参与」做成主转化，而不是纯品牌册页。

公开资料中，软通系常见对外名称为「雏英计划」等校园培养品牌；**本项目按需求方口径使用「雏鹰计划」**。若对外统一品牌名变更，以业务方书面确认为准并修订本文。

### 2.2 目标

1. 访客能在 3 分钟内理解雏鹰计划「是什么 / 适合谁 / 如何加入」。  
2. 意向者能完成**加入计划报名**；已成为雏鹰的用户能完成**活动报名**并查看个人参与与积分相关信息。  
3. 管理者能在后台完成内容发布、报名审核、活动配置与积分相关运营（细则待补）。  
4. 架构上允许后续增删功能模块，而不推翻前台信息架构。

### 2.3 效果评估（首期建议，含待核实）

| 指标 | 建议口径 | 周期 | 状态 |
| --- | --- | --- | --- |
| 官网有效访问 | UV / PV | 上线后 30 天 | `[待核实]` 基线 |
| 加入报名提交数 | 成功提交次数 | 同上 | `[待核实]` 目标值 |
| 加入报名转化率 | 提交数 / 报名页 UV | 同上 | `[待补充]` |
| 活动报名完成率 | 成功报名 / 活动详情 UV | 按活动 | `[待补充]` |
| 管理者后台周活 | 有操作的管理员账号数 | 周 | `[待补充]` |

## 4. 功能关系总览

```
雏鹰计划宣传官网系统
├── 宣传展示
│   ├── 浏览计划介绍 [平级]
│   └── 浏览日常动态 [平级]
├── 账号与身份
│   ├── 登录 [平级]
│   └── 登出 [平级]
├── 加入计划
│   ├── 提交加入报名 [平级]
│   └── 查看加入报名状态 [平级]
├── 活动运营
│   ├── 浏览活动列表与详情 [平级]
│   ├── 报名活动 [平级]
│   └── 取消或修改活动报名 [扩展]
├── 积分管理
│   ├── 查看我的积分与明细 [平级]
│   ├── 配置积分规则 [平级]
│   └── 登记积分变动 [平级]
│       └── （可选）活动签到自动加分 [扩展，待定]
└── 后台管理
    ├── 管理宣传内容 [平级]
    ├── 审核加入报名 [平级]
    ├── 管理活动 [平级]

    ├── 管理用户与权限 [平级]
    └── 查看运营数据看板 [扩展]
```

关系说明：

- 「报名活动」与「登记积分变动」为**平级**业务能力；是否在报名成功或签到后自动加分，用 **extend** 挂接，规则未定时不画成 include。  
- 「审核加入报名」是管理者侧能力，与「提交加入报名」平级对应，不是父子。

## 5. 功能需求详述

### 5.1 浏览计划介绍

**操作者**：访客、雏鹰  
**前置条件**：可访问官网前台  
**后置条件**：无写库；可上报 `page_view`

#### 功能关系

- 父功能：宣传展示  
- 关系：平级于「浏览日常动态」

#### 处理流程

**主流程**：打开首页或介绍页 → 阅读模块化内容（定位 / 路径 / 亮点 / FAQ）→ 点击主 CTA 进入加入报名或活动列表。  
**分支流程**：从导航栏目直达子锚点。  
**异常流程**：内容未发布时展示占位或隐藏栏目。

#### 逻辑自检

| 步骤 | 输入 | 验证 | 执行 | 反馈 |
| --- | --- | --- | --- | --- |
| 打开介绍 | URL | 页面存在 | 拉取已发布内容 | 渲染介绍模块 |
| 点击 CTA | 点击 | 链接有效 | 跳转目标页 | 进入报名或活动 |

#### 原型与交互说明

| 区域 | 规则 |
| --- | --- |
| 首屏 | 计划名 + 一句话价值 + 主按钮「加入雏鹰」；次按钮「查看活动」 |
| 内容区 | 分块呈现，避免首屏堆统计条；对标宣传官网「叙事优先」 |
| 预览 | 管理者在后台可预览未发布稿（P2，可后置） |

#### 处理流程

### 5.3 提交加入报名

**操作者**：访客（或未通过审核的账号）  
**前置条件**：加入报名通道开启；表单字段配置可用  
**后置条件**：生成加入申请单；状态为待审核；上报 `join_apply_submit`

#### 功能关系

- 父功能：加入计划；与「查看加入报名状态」平级  
- 「审核加入报名」为其管理侧对应能力（平级，不同角色）

#### 处理流程

**主流程**：进入加入报名页 → 填写必填项 → 提交 → 看到成功页与后续说明。  
**分支流程**：已登录用户自动带出基础资料。  
**异常流程**：通道关闭、重复提交、校验失败、服务异常。

#### 逻辑自检

| 步骤 | 输入 | 验证 | 执行 | 反馈 |
| --- | --- | --- | --- | --- |
| 填写 | 表单字段 | 必填/格式 | 暂存可选 | 字段级错误提示 |
| 提交 | 表单快照 | 通道开启且无进行中申请 | 创建申请 | 成功页 / 错误原因 |

#### 原型与交互说明

| 区域 | 规则 |
| --- | --- |
| 表单 | 字段清单 `[待补充]`（姓名、联系方式、学校/专业等以业务为准） |
| 提交按钮 | 防重复点击；成功后给出「等待审核」说明 |
| 预览 | 提交前可回看已填项（建议 P1） |

### 5.6 报名活动

**操作者**：雏鹰  
**前置条件**：已登录且身份为雏鹰；活动开放报名；未超额（规则待定）  
**后置条件**：生成活动报名记录；上报 `activity_signup_submit`；若配置了自动积分则触发积分扩展（待定）

#### 功能关系

- 父功能：活动运营  
- 与「浏览活动详情」平级；自动加分作为 **extend**（未定规则前不做硬依赖）

#### 处理流程

**主流程**：详情页点击报名 → 确认信息 → 提交成功 → 进入我的活动。  
**异常流程**：非雏鹰、已报名、已截止、名额满、系统错误。

#### 逻辑自检

| 步骤 | 输入 | 验证 | 执行 | 反馈 |
| --- | --- | --- | --- | --- |
| 报名 | activity_id, user | 身份/窗口/名额/重复 | 写报名记录 | 成功或错误码文案 |

#### 原型与交互说明

| 区域 | 规则 |
| --- | --- |
| 确认弹层 | 展示活动名、时间；二次确认 |
| 成功态 | 提供「查看我的活动」入口 |

### 5.7 查看我的积分与明细

**操作者**：雏鹰  
**前置条件**：已登录为雏鹰  
**后置条件**：可上报积分页浏览

#### 功能关系

- 父功能：积分管理；与管理者「配置规则 / 登记变动」平级（不同角色）

#### 处理流程

**主流程**：进入我的积分 → 看余额 → 翻阅明细（时间、变动值、原因）。  
**异常流程**：无流水展示空态。

#### 逻辑自检

| 步骤 | 输入 | 验证 | 执行 | 反馈 |
| --- | --- | --- | --- | --- |
| 查余额 | user_id | 本人 | 汇总可用积分 | 余额数字 |
| 查明细 | 分页 | 本人 | 查询流水 | 明细列表 |

#### 原型与交互说明

| 区域 | 规则 |
| --- | --- |
| 规则说明 | 只读展示当前生效规则摘要；完整规则页可链出 |
| 明细 | 正负分颜色区分；原因文案可读 |

> 积分获取/消耗具体规则见构想文档待补清单；**未定前本功能只做展示骨架与流水模型**。

### 5.8 配置积分规则 / 登记积分变动（管理者）

**操作者**：管理者  
**前置条件**：具备积分管理权限  
**后置条件**：规则生效或流水落库；上报 `points_change`（登记时）

#### 处理流程

**主流程（配置）**：进入积分规则 → 新增/编辑规则 → 保存生效。  
**主流程（登记）**：选择雏鹰 → 输入变动值与原因 → 确认 → 余额更新。  
**异常流程**：无权限、数值非法、对象不存在。

## 6. 非功能需求详述

1. **信息架构**：前台以「了解 → 加入 → 活动 → 我的」为主路径；后台以「内容 / 报名 / 活动 / 积分 / 用户」分栏。  
2. **移动优先**：宣传与两类报名必须在手机浏览器可用。  
3. **安全**：管理写操作鉴权；积分调账留审计日志（操作者、时间、前后余额）。  
4. **变更友好**：功能模块可开关；文案与活动配置尽量后台化。  
5. **品牌**：视觉与软通智慧对外规范对齐 `[待核实设计规范]`。
