# 数据看板改进方案

> 日期：2026-08-05  
> 范围：管理后台「数据看板」`/admin/dashboard`  
> 关联：`docs/prd/AI创新大赛-产品与答辩要点.md`、`globaluser-后台-数据看板.md`  
> 现状问题：近 7 日趋势图不可读（量级差过大、缺坐标）；六个统计卡片点击后仅进入原有功能模块，缺少看板自身的信息价值。

---

## 1. 目标与验收

看板应回答运营三句话，而不是再当侧栏快捷方式：

1. **现在堆了什么？**（待审加入 / 待审积分 / 进行中活动）  
2. **最近一周动得怎样？**（报名、积分发放是否异常）  
3. **下一步点哪里处理？**（带筛选的待办，而不是裸跳列表首页）

### 成功标准

| # | 标准 |
| --- | --- |
| 1 | 近 7 日即使有一天积分暴增，其余日期仍清晰可辨 |
| 2 | 从看板 **≤2 次点击** 可进入某条待审详情 |
| 3 | 答辩约 30 秒内能指图说清：「积压在积分审批 / 报名是否平稳」 |
| 4 | 关闭 AI 摘要后，看板仍独立可用（AI 为增强，非唯一卖点） |

点击卡片：允许跳转，但须为 **带状态的深链**（例如待审积分 → `/admin/point-apps?status=pending`），并在本页先给出「为什么重要」的摘要。

## 2. 图表改进

### 2.1 问题根因

近 7 日「积分」与「报名」量级可能相差极大（例如某日积分柱冲顶），叠在同一 Y 轴时，早期日期会被压成缝；再缺少 Y 轴刻度与网格，图几乎不可读。

### 2.2 推荐改法（由易到难）

| 方案 | 做法 | 效果 |
| --- | --- | --- |
| A（最快） | **拆成两张图**：报名柱状 + 积分柱状/折线，各用自己的 Y 轴 | 立刻可读 |
| B | 一张图但 **双 Y 轴**（左报名、右积分），图例可点显隐 | 仍可对比、不互压 |
| C | 积分用 **折线**、报名用 **柱**，并加横向网格 + Y 轴刻度 | 观感再升一档 |
| D | 空值日显示 0；hover 显示「日期 / 报名 n / 积分 ±m / 笔数」 | 便于答辩指点 |

若坚持一张组合图：优先 **B + hover**，不要再做无刻度的堆叠柱。

### 2.3 视觉底线

- 固定图高；柱体圆角；图例置于上方  
- Y 轴从 0 起；整数刻度  
- 颜色沿用品牌：报名琥珀、积分青绿  
- 柱基线贴齐日期轴，避免「柱子悬空」

## 3. 六个统计卡片

保留现有指标，为每张卡增加 **看板语义**（指标 + 一句解释 + 一条深链）：

| 卡片 | 现状 | 改进 |
| --- | --- | --- |
| 活跃雏英 | 纯数字 | 副文案「较上周 ±n」；点击 → 用户管理且 `role=eagle&status=active` |
| 待审加入 | 跳列表 | 本页下列出 Top 3 待审（姓名/时间）+「查看全部」深链 `status=pending` |
| 待审积分 | 跳列表 | Top 3（申请人/类型/申请分）+ 可选「AI 建议优先审」标记 |
| 进行中活动 | 跳活动 | 展示 1 个进行中标题 + 报名数；点击进该活动报名名单 |
| 近 7 日报名 | 跳相关模块 | 点击高亮趋势「报名」，或打开近 7 日明细抽屉 |
| 近 7 日积分 | 跳流水/审批 | 保留「n 笔流水」副文案；点击打开近 7 日入账明细 |

原则：**重列表仍回原模块**；看板先完成「看见问题」。

## 4. 布局重构建议

```
[标题 数据看板]                    [刷新] [近7日 ▾]

┌── 待办区（左约 2/3）─────────────┬── 速览（右约 1/3）──┐
│ 待审积分 n · 待审加入 m           │ 活跃雏英 / 进行中   │
│ ┌ 队列预览表（5～8 行）┐          │ 近7日报名 / 积分   │
│ └ 行点击进详情 ─────────┘          │ 迷你趋势（火花线） │
└──────────────────────────────────┴───────────────────┘

┌── 近7日趋势（报名 | 积分 分图或双轴）───────────────────┐
│ 图例可切换 · hover 明细                                  │
└──────────────────────────────────────────────────────────┘

┌──（可选）运营提示 / AI 摘要 ─────────────────────────────┐
│ 例：「待审积分已积压至 31，建议优先处理类型一」           │
└──────────────────────────────────────────────────────────┘
```

大数字墙收成右侧速览；**中间留给待办队列**——这才是管理后台看板的核心价值。

## 5. AI 创新赛可叠加能力

不必在看板上再塞通用聊天框，用 **「洞察条」** 即可：

| 能力 | 说明 |
| --- | --- |
| 积压预警 | 待审积分 / 待审加入超过阈值 → 文案 + 一键深链到已筛待审列表 |
| 异常日解释 | 先规则（对比近 7 日均值）；可选模型生成一句话摘要 |
| 优先审谁 | 按等待时长或 AI 预审风险分排序队列（与积分审批预审打通） |
| 答辩话术 | 规则算指标与阈值，AI 写「今日运营建议」；可关闭 |

评委看到的是：**数据驱动运营 + AI 辅助分诊**，而不是「卡片跳菜单」。

---

## 6. 落地分档

| 档 | 内容 | 大约工作量 |
| --- | --- | --- |
| **MVP（1～2 天）** | 趋势拆双图或双 Y 轴；加刻度/hover；卡片深链带 query | 低 |
| **标准（3～5 天）** | 待办预览表；卡片副指标（环比）；进行中活动摘要 | 中 |
| **赛点（再 +1～2 天）** | 积压预警 + AI 一句话摘要 + 与预审风险联动排序 | 中 |

**建议顺序：** 先做 MVP 图表与深链 → 再叠待办预览 → 最后加洞察条。

---

## 7. 方案一句话

把看板从「六个快捷方式 + 难看柱图」改成 **「待办队列 + 可读趋势 + 带筛选深链」**；大赛再加一层 **积压/异常的一句话洞察**。
