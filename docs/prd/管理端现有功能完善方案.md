# 管理端现有功能完善方案（用户操作视角）

> 日期：2026-08-05（修订于同日实测后）  
> 范围：管理后台已有模块（控制台、内容、知识库、加入审核、活动/课程、积分类型与审批、用户、周报、数据看板、权限）  
> 原则：**不大规模加功能**；只把现有能力做顺、做懂、做少点错  
> 依据：当前前后端实现走查 + **真人实测走完三条主链路后的体验反馈**；看板专项另见 `数据看板改进方案.md`  
> 实测记录：用演示三角色（雏英/管理员/超管）完整走完「加入→开户→登录→报名→交心得→AI预审→审批→积分入账」全链路，以下补充项均来自实际操作的卡顿点。

---

## 1. 文档目的

管理员不是「功能清单用户」，而是在固定任务里找最短路径。本方案从 **谁、在什么心态下、点了几步、哪里卡住** 出发，给出可落地的完善项。

**不做的事（本阶段明确排除）：**

- 新业务模块、新权限包拆分、批量审批引擎、复杂报表平台  
- 重构技术栈或重做整套后台视觉  

**要做的事：**

- 修操作回路断点（筛不回去、看不懂 ID、关键动作无确认）  
- 统一列表/详情的返回与反馈  
- 让「审核 / 发布 / 开户」等高风险动作更安全、更好交接

## 2. 管理员是谁、每天在干什么

### 2.1 角色与典型任务

| 角色 | 典型任务（按频次） | 成功标准（用户语言） |
| --- | --- | --- |
| 日常运营管理员 | 审加入、审积分、改活动/课程、改首页内容 | 「堆的单子清得动，改完前台立刻对」 |
| 内容/知识库同学 | 改 CMS、维护知识库文档 | 「改完能预览，别搞丢草稿」 |
| 超管 | 加管理员、改授权、看全局是否卡壳 | 「谁能干什么一目了然，别误停用」 |

### 2.2 三条主操作链路（现有系统）

```
链路 A · 加人进计划
  控制台/看板「待审加入」→ 加入列表(待审) → 详情 → 通过/驳回
  →（通过）看见一次性账号密码 → 交给申请人登录

链路 B · 发积分
  控制台/看板「待审积分」→ 积分列表(待审) → 详情
  →（可选）生成 AI 建议 → 改分值/填驳回原因 → 通过入账或驳回

链路 C · 配活动/课程与内容
  活动或课程列表 → 编辑存草稿/发布 →（可选）看报名/学习名单
  内容运营选块 → 存草稿/发布
```

完善重点：**缩短链路里的犹豫与返工**，而不是再插第四条大链路。

### 2.3 用户心智 vs 现状落差

| 用户以为 | 实际常见情况 | 完善方向 |
| --- | --- | --- |
| 「全部」能随时清筛选 | 部分下拉里「全部」选项 `disabled`，选过后清不掉 | 可再次选「全部」或提供「清除筛选」 |
| 列表里是「谁申请的」 | 积分列表显示 `userId` | 显示姓名/邮箱 |
| 通过加入 = 事情做完 | 密码只展示一次且不好复制；已有邮箱时无说明 | 复制按钮 + 明确提示 |
| 点卡片 = 去处理积压 | 部分仅进模块首页，筛选状态靠猜 | 深链带 `status=` 等 query |
| 保存成功会有提示 | 活动/课程保存常静默 | 统一成功 Toast |
| 危险操作会再问一句 | 加入通过、发布、积分通过常无确认 | 补确认（文案说清后果） |

## 3. 全站共性完善（优先做，一次惠及多模块）

### 3.1 列表筛选与检索

| 问题 | 用户操作逻辑 | 完善做法 |
| --- | --- | --- |
| 「全部」无法回选 | 先筛「待审」再想看全部 → 卡死 | 启用「全部」或旁置「清除」 |
| 加入搜索须按 Enter | 习惯点搜索或输入即搜 | 保留 Enter，加「搜索」按钮；文案提示 |
| 活动有服务端关键字、UI 无入口 | 想按标题找活动却只能翻表 | 列表加关键字框（对接已有 `q`） |
| 课程关键字每个字都请求 | 输入卡顿、像坏了 | 防抖 300ms 再请求 |

### 3.2 人读信息，少露内部码

| 位置 | 现状 | 完善 |
| --- | --- | --- |
| 积分审批列表 | `userId` | 显示名 + 邮箱（ID 可次要） |
| 加入详情面包屑 | `详情 #123` | 申请人姓名或「某某的申请」 |
| 积分详情审批人 | `审批人 #id` | 显示名 |
| 用户「授权摘要」 | 英文 permission code | 中文权限包名称 |
| 活动报名名单 `status` | 英文原串 | 「已报名」等中文 |

### 3.3 危险动作确认与成功反馈

| 动作 | 建议确认文案要点 | 成功反馈 |
| --- | --- | --- |
| 加入·通过 | 将创建雏英账号（若邮箱未占用） | Toast + 账号区高亮 |
| 加入·驳回 | 已有原因框即可；提交前可二次确认 | Toast |
| 积分·通过并入账 | 将写入积分流水，不可当没事 | Toast「已入账 x 分」 |
| 活动/课程·发布/下架 | 前台将可见/不可见 | Toast |
| 内容·发布 | 前台对应块将更新 | Toast（已有文案可加强） |

停用用户、删除内容/知识库/积分类型：**保持现有 confirm**，文案统一语气即可。

### 3.4 壳层导航

| 问题 | 完善 |
| --- | --- |
| 无「返回前台」 | 顶栏增加「回前台」→ `/` |
| 未登录仍见后台壳 | 进入 `/admin` 即引导登录，或壳层同步鉴权 |
| 演示登录按钮常显 | 仅开发/演示环境显示，或收进「演示」折叠 |
| 无权限页过泛 | 提示「缺少：xxx 权限」，链回控制台 |

### 3.5 空状态与返回

- 各列表统一：插画或短文案 + 一句引导（「暂无待审，去看看活动」等，按模块写死即可）  
- 详情/编辑页统一「返回列表」，并尽量保留原筛选 query  
- 筛选无结果：说明「当前筛选无数据」，提供清除筛选

## 4. 分模块：操作逻辑与完善项

下列每节格式：**用户怎么走 → 卡点 → 完善（仍属现有能力）**。

### 4.1 控制台 `/admin`

**操作逻辑：** 上班先看积压数字，再点「去审核」进入加入/积分。

**卡点：** 无 `dashboard` 时数据偏少且失败被吞；统计卡不可点；无手动刷新。

**完善：**

1. 待审加入 / 待审积分数字 **可点**，深链到已筛待审列表（与看板一致）。  
2. 增加「刷新」或进入页自动拉取。  
3. 快捷入口补齐高频：课程、用户（有权限才显示），文案与侧栏一致。  

### 4.2 加入审核

**操作逻辑：** 列表找待审 → 打开详情读动机 → 通过则 **立刻要交接账号**；驳回则写原因。

**卡点：**

- 通过无确认，误点即开户  
- 一次性密码无法一键复制  
- 邮箱已存在时通过成功但无账号块，管理员以为失败或不知下一步  
- 筛选「全部」难恢复  

**完善：**

1. 通过前确认：「将审核通过；若该邮箱未注册将创建雏英账号。」  
2. 账号区：**复制邮箱**、**复制密码**、可选「复制账号+密码」；再次强调「请立即交接，离开后不可再查」。  
3. 邮箱已存在：明确文案「申请已通过；该邮箱已有账号，未生成新密码。请通知对方使用原账号登录。」  
4. 修复筛选；空列表区分「没有申请」与「没有待审」。  

### 4.3 积分审批

**操作逻辑：** 打开待审 → 读心得/专项 →（可选）看 AI 建议 → 改分或写驳回 → 提交。

**卡点：**

- 列表看不出是谁，只能进详情  
- AI 建议与表单字段未打通，要人工抄  
- 通过无确认即入账  

**完善：**

1. 列表展示申请人显示名/邮箱、类型中文名。  
2. AI 区增加「填入建议分值」「填入建议驳回理由」一键写入现有输入框（**不自动提交**）。  
3. 通过/驳回补确认；成功 Toast。  
4. 关联活动/课程标题可链到管理端编辑页或前台详情（只读链即可）。  

### 4.4 活动管理 / 课程管理

**操作逻辑：** 列表找草稿 → 编辑字段 → 存草稿或发布 → 需要时看名单。

**卡点：**

- 发布校验（如通道截止）失败提示含糊  
- 线下封面仅 URL、线上可上传，操作不一致带来困惑  
- 报名/学习名单状态英文；名单无法回跳用户  
- 活动缺关键字搜索  

**完善：**

1. 「保存并发布」前做前端必填检查（通道截止、时间先后），错误贴在字段旁。  
2. 统一成功/失败 Toast。  
3. 名单状态中文；邮箱可复制；可选链到用户管理搜索（`?q=email`）。  
4. 活动列表补关键字；课程搜索防抖。  
5. 编辑页增加「查看前台」链接（已发布时）。  

> 封面是否也支持上传：若只是把现有上传组件接到线下封面，算 **完善现有编辑能力**，不算新业务。

### 4.5 内容运营 / 知识库

**操作逻辑：** 选一块/一篇 → 改 → 存草稿或发布；知识库还要服务前台助手。

**卡点：** 不知前台长什么样；内容块 key 难懂；知识库新建与编辑面板叠在一起。

**完善：**

1. 内容块旁标注中文用途（如 `home_plan_promo` →「计划介绍素材」）。  
2. 「在前台查看」链到 `/content/:key` 或 `/about`（按块约定）。  
3. 发布补确认；保存成功明确提示。  
4. 知识库：编辑时收起「新建」区，避免双表单；保留现有纯文本编辑即可。  

### 4.6 积分类型

**操作逻辑：** 改名称/默认分、启停、偶发新增/删除。

**卡点：** 空列表无引导；启停无确认；接口里申请人改分开关 UI 未露出（若产品仍要该能力，仅补现有字段编辑，不新造类型体系）。

**完善：**

1. 空状态 +「添加第一个类型」。  
2. 启停二次确认（停用会影响前台可选模板）。  
3. 若保留 `allowApplicantEditPoints`：在行内增加开关，文案用人话。  

### 4.7 用户管理 / 权限管理

**操作逻辑：** 搜人 → 停用/启用；超管加人并勾权限；细调授权去权限页。

**卡点：** 授权在「用户摘要 / 添加管理员 / 权限页」三处出现，心智分裂；授权摘要是英文码；无结果时空表。

**完善：**

1. 用户页「授权摘要」用中文包名；旁注「修改请前往权限管理」并带上该用户深链（若暂不能带 id，则链到权限页并文案说明选人）。  
2. 筛选无结果空状态 + 清除筛选。  
3. 停用确认文案写明：「停用后无法登录及调用需登录接口。」（已有 confirm 则加强文案）  
4. **不**在本阶段做重置密码新产品；若仅补「超管创建时已设密码」的说明文案即可。  

### 4.8 数据看板

专项方案见 **`数据看板改进方案.md`**。本处只强调与全站一致的操作逻辑：

- 卡片与待办 = **带筛选深链**，不是裸进模块  
- 趋势图先保证可读（双轴或分图）  
- 日明细抽屉内条目尽量可点进详情  

### 4.9 周报管理（侧栏已有）

**操作逻辑：** 按雏英查看周报汇总（现有能力）。

**完善（小步）：** 列表人读字段统一、空状态、返回用户管理；生成/刷新若已有按钮则补加载态与失败重试文案。不扩展成新的报告产品线。

## 7. 验收方式（用户任务脚本）

用真实管理员账号走一遍，不要求新功能出现，只要求路径顺：

1. **加人：** 待审加入 → 通过 → 一键复制账号密码 → 用该账号能登录前台。已存在邮箱时文案正确。  
2. **发分：** 待审列表能认出申请人 → 详情 →（可选）AI 填入建议分 → 确认通过 → 雏英积分明细可见。  
3. **发活动：** 编辑缺通道截止时前端拦住 → 补全后发布成功有提示 → 前台可见。  
4. **筛选：** 任意列表筛「待审」后再回「全部」成功。  
5. **进出：** 后台顶栏一键能回前台；详情页能回到带筛选的列表。

## 9. 实测中发现的具体缺陷（P0，已复现）


| # | 问题 | 复现路径 | 严重度 |
| --- | --- | --- | --- |
| 1 | **筛选「全部」disabled 无法恢复** | 用户管理/积分审批/加入审核：选择角色或状态筛选后，想切回「全部」看所有数据 → 下拉框中「全部」选项为 `disabled`，无法选中 | 🔴 高 |
| 2 | **通过加入/积分无确认** | 加入审核点「通过」→ 直接开户生成密码，无二次确认。积分审批同理，点「通过」直接入账 | 🔴 高 |
| 3 | **AI 洞察栏显示原始 JSON** | 数据看板 AI 洞察区若 DeepSeek 返回 JSON → 前端直接渲染 `{"summary":"...","alerts":[]}` 而非格式化文本 | 🔴 高 |
| 4 | **一次性密码无复制按钮** | 加入通过后显示的账号密码区域没有一键复制，管理员需手动选中→Ctrl+C | 🟡 中 |
| 5 | **邮箱已存在时开户静默** | 审批通过一个已注册邮箱的加入申请 → 返回成功但无 `account` 字段 → 管理员不知道发生了什么 | 🟡 中 |
| 6 | **AI 建议分值未关联表单** | 积分详情页 AI 建议面板给了「建议分值 12」和「驳回原因草稿」，但需手工抄入旁边的输入框 | 🟡 中 |
| 7 | **保存/发布成功无反馈** | 活动编辑/内容块编辑保存或发布后，页面静默刷新，无 Toast 提示。除了看路由变化，管理员无法确认操作成功 | 🟡 中 |
| 8 | **内容块 key 不可读** | `demo_block_1`、`home_plan_promo` 等 key 对运营人员无意义，不知道对应首页哪个位置 | 🟢 低 |
| 9 | **首页「向下滚动」文字闪烁** | Hero 区 bounce 动画的 `transform` 覆盖了 `translateX(-50%)` 定位，导致文字水平抖动 | 🟢 低 |
| 10 | **周报生成无加载态提示** | 点击「生成周报」→ 按钮短暂 disabled，但对 50+ 雏英生成可能需要数十秒，用户不知道是否卡死 | 🟢 低 |

## 10. 一句话总结

管理员端完善 = **顺着「审加入 → 审积分 → 发活动/内容」三条日常路径，把看不懂、点不回去、怕点错、做完没反馈四处磨平**；不靠堆新菜单取胜。

**实测结论（2026-08-05）**：用演示三角色完整走通全链路约 3 分钟，核心功能可用。但上述 10 个缺陷中 #1~#3 属于高频操作卡顿（每次审核/每次看板都会遇到），建议优先修；#4~#7 影响操作效率但可绕过；#8~#10 属于体验打磨。
